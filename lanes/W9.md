## Nothing in the vocabulary was hand-written

`shared/bx.json` is byte for byte what `latte-bx vocabulary` prints. Not one row
was typed here, and none may be: a hand-written vocabulary that drifts from the
compiler is worse than none, because the drift gate would then be green about a
lie. Everything the grammar and the extension paint or offer as latte's own is
derived from that file.

The two places that are **not** derived from a table are named, and each is
checked against one so it cannot go stale silently:

| what | where | the check |
|---|---|---|
| which `$` word takes a header, a call, or a form of its own | `BLOCK_SHAPE` in `scripts/lib/tmlanguage.mjs` | a name in `bx.blocks` with no shape throws at generate time |
| which language a raw-text element's body is written in (`script`→`source.js`, `style`→`source.css`) | `RAW_TEXT_EMBED`, same file | a name in `bx.rawTextElements` with no entry throws |
| `key`/`ref`/`attrs` take a value, `preserve`/`live` are bare | `RESERVED_SHAPE`, same file | a name in `bx.reservedAttributes` with no shape throws |
| `on:` and `bind:` are latte's; the rest of `bx.namespaces` are XML | `OWN_NAMESPACES`, same file | either one missing from the table throws |
| the four interpolation forms | `INTERPOLATIONS`, same file | a name in `bx.interpolations` not listed throws |

That is the same discipline `CONTEXTUAL_MODIFIERS` already followed in that
file: missing an entry is a build error, not a silently unpainted keyword.

## How to regenerate `shared/bx.json`

`latte-bx` must be built first; there is no checked-in binary. From the **latte**
checkout, not from editors:

```bash
cd /Users/julfikar/Documents/PassionFruit.nosync/beans-lang/community-libs/latte
export BEANS_ROOT=/Users/julfikar/Documents/PassionFruit.nosync/beans-lang/beans
export BEANSC="$BEANS_ROOT/build/beansc"
export BEANS_RUNTIME="$BEANS_ROOT/runtime/beans_rt.c" \
       BEANS_STDLIB="$BEANS_ROOT/stdlib/std" \
       BEANS_ENCODING="$BEANS_ROOT/runtime/encoding" \
       BEANS_NET="$BEANS_ROOT/runtime/net" \
       BEANS_LOG="$BEANS_ROOT/runtime/log"
"$BEANSC" build examples/latte_bx.b -o /tmp/latte-bx        # ~1.3s
/tmp/latte-bx vocabulary > <editors worktree>/shared/bx.json
cd <editors worktree> && npm run generate
```

Notes a successor needs:

- The compiler must be **0.1.40**; `beans/build/beansc` in this workspace is.
- `latte-bx`'s entry is `examples/latte_bx.b`, not a root-level `main.b` — latte
  is `kind library` and a library may only hold a program entry under
  `examples/` or `tests/`.
- Building writes `.ll` scratch into `community-libs/latte/build/`, which is
  gitignored. Nothing tracked in latte is touched. Put the binary somewhere else
  (`/tmp`), as above.
- **Verified 2026-09-08:** the printed string is byte-identical to latte's own
  golden `community-libs/latte/tests/w2_editor_data.out` (6506 bytes). If those
  two ever disagree, latte's gate is the one to believe.

`node scripts/generate.mjs --check --bx <path>` reads the vocabulary from
somewhere else, which is how the shape check is exercised against a file that is
deliberately wrong. It is a real option, documented in the script's header, not
a test hook.

### 1. `buildBxData`'s `undefined`-dropping bug — fixed, and the fix bites

W2's finding: `buildBxData` destructured nine keys and handed them to
`JSON.stringify`, which drops every `undefined` without a word. A wrong-shaped
`bx.json` therefore produced a `bx-data.ts` with eight of nine tables **gone**
and passed both `npm run generate` and the drift gate; `tsc`'s 21 errors all
named a field and none named a missing table.

What is there now, in `scripts/lib/language-data.mjs`:

- `BX_SCHEMA` — the shape, in one place, driving the check, the emitted
  `BxVocabulary` interface and the emitted object, so a table cannot be
  half-added.
- `bxProblems(data)` — every fault, not the first. It fails in both directions:
  a table missing, empty, of the wrong type, or a row short a field; **and** a
  table or a row field latte grew that the editor has never heard of.
- `loadBxData(path)` throws on any of it, and is the one path both the write and
  the `--check` run take.

**The deletion proof, run 2026-09-08.** Replacing `const problems =
bxProblems(data)` with `const problems = []` in `loadBxData` makes two tests
fail:

```
not ok 2 - a missing table is named, not silently dropped
  error: 'Missing expected exception.'
not ok 9 - the generator itself fails on one, rather than emitting empty tables
# tests 63 / pass 61 / fail 2
```

Restored, 63/63. `JSON.stringify` still drops an `undefined`, so the check is
the only thing between a wrong-shaped vocabulary and a gutted `bx-data.ts` —
which is why the deletion has to fail, and does.

### 2. `buildBxTmLanguage` — inverted

`scripts/lib/tmlanguage.mjs`. Markup is the default and Beans appears only where
latte puts it. By context:

| context | state |
|---|---|
| markup outside `<beans>` | **done.** Elements, components (`<ui.Button>`, by the last-dotted-segment rule), close tags, `<!-- -->`, `<!DOCTYPE>`, character entities, `\}` / `\{` escapes, and a `<` that opens nothing painted `invalid.illegal.unexpected-lt` — which is latte's own refusal |
| Beans inside `<beans>` | **done.** A raw-text region handing the whole body to `source.beans`; nothing inside is scanned, so a `<`, a `$` or a brace in there is Beans. Tested: a `List<int>` and a `"<div>"` inside it produce no tag token |
| `<script>` / `<style>` | **done.** Raw-text regions handing the body to `source.js` / `source.css`. Generated from `bx.rawTextElements` |
| `$if` / `$for` / `$match` | **done.** Sigil, keyword, and the header as Beans up to the first `{` at the header's own level — with balanced `(…)` and `[…]` helpers, so a closure in a header does not end it early |
| `else` / `else if` | **done**, behind a lookahead so the English word in prose stays text |
| `${ }` / `$( )` / `$$` / `$chain` | **done** |
| `$html( )` | **done**, painted `keyword.other.unsafe.bx` |
| `$slot` | **partial.** `$slot`, `$slot(expr)`, `$slot:name` and the `as` keyword are painted; what follows `as` in the typed-parameter form (`as p: Type {`) reads as markup text. Painting it needs the parser's "a body is what tells a definition from a placement" rule, which a regex cannot make |
| `on:` / `bind:` | **done**, generated from `bx.events`, `bx.bindings` and `bx.conversions`. An event or binding latte does not have is painted invalid |
| `key` / `ref` / `attrs` / `preserve` / `live` | **done**, generated from `bx.reservedAttributes` and painted apart from the attributes that reach the wire |
| a `$match` arm pattern | **partial.** Painted as Beans when the arm starts a line and ends `=> {`; an arm written inline with its match reads as text |

The grammar also agrees with the compiler about what is *wrong*: an unknown
`on:` event, an attribute namespace outside latte's five, a boolean attribute
given a string (`disabled="false"` is a disabled control in every browser), any
attribute whose name is three bytes or longer and starts with `on`, and — on a
**component** tag, whose rules are not the element rules — `on:`, `attrs`,
`preserve` and a parameter name that is not a Beans identifier.

**It is deliberately flat.** A `$if` body is not a region; it is the same markup
rules with a `{` before and a `}` after. A balanced-brace region would let a
stray `{` in running text — which latte reads as ordinary text — swallow the
rest of the file. The cost is the two "partial" rows above.

### 3. `bx-model.ts`, `bx.ts`, the language configuration — rewritten

- `bx-model.ts` scans a markup document. New states: markup `text`, `beans`,
  `raw`, `comment`, `expr`, plus the old `tag`/`attr`/`value`. It mirrors four
  scanners from latte's `lex.b` — `end_of_comment`, `end_of_raw_string`,
  `end_of_string`, `end_of_group`, plus `find_header_brace` and `end_of_chain` —
  rather than approximating them, because a brace means four different things in
  Beans and crema's driver got it wrong on a raw literal.
- `bx.ts` drops the colour provider entirely: latte has no colour table and a
  swatch beside `class="…"` would be an invention. It offers the `$` blocks with
  bodies, the interpolation forms, the events (with the class each handler
  takes), the bindings and conversions, the reserved attributes, the boolean
  attributes with the reason the string form is refused, the URL attributes with
  the scheme allowlist, and the elements latte has a *rule* about — each with
  its rule. It offers **no list of HTML element names**, because latte has none.
- `bx-language-configuration.json`: the comment is `<!-- -->`, not `//`. A `//`
  in markup is two characters that reach the page.

## Things worth knowing that cost time

- **vscode-textmate disables a whole rule whose `include` it cannot resolve.**
  The `<script>` raw-text region silently never fired in a harness without
  `source.js`, and the symptom was "the body reads as markup" — the opposite of
  what VS Code does. `test/bx.test.mjs` supplies stub grammars for `source.js`
  and `source.css` for exactly this reason, and says so.
- **Oniguruma treats `[` inside a character class as a nested class** (Ruby
  syntax), so `[^\][]` is `premature end of char-class`. Write `[^\[\]]`.
  `scripts/…/checkre.mjs`-style compilation of every regex in the generated
  grammar is how that was found; a bad regex otherwise surfaces as a stack trace
  from `loadWASM`.
- Zero-width `begin`/`end` pairs with lookbehind (`(?<=<script)` … `(?=>)`, the
  shape the HTML grammar uses) did not work here. The one-line open tag in the
  `begin` does.
