## The facts this lane starts from (measured by latte's W2, not re-derived)

1. `shared/bx.json` feeds **exactly one** of `generate.mjs`'s 27 outputs:
   `vscode/src/bx-data.ts`. The `.bx` TextMate grammar (`buildBxTmLanguage`)
   and the tree-sitter inputs (`buildGrammarData`) are built from
   `shared/language.json`, not from `bx.json`.
2. **Nothing in the old `bx.json` survives.** All nine keys were crema's:
   `tags` (2), `flags` (128 Tailwind utilities), `ramps`, `stepTables`,
   `counts`, `texts`, `values`, `colors` (391), `events` (17 GPUI events).
   latte has an equivalent for none of them; `events` shares only its key name.
3. **The two dialects are different languages sharing an extension.** crema's
   `.bx` is a Beans file with tag expressions in function bodies — `<` opens a
   tag only where a name does not end just before it, and `"…<div>…"` is a
   string. latte's is a **markup document**: outside `<beans>` a `<` *always*
   opens a tag, and that same text *is* markup. `buildBxTmLanguage` had to be
   inverted, not adjusted.
4. **The toolchain bug W2 found.** `buildBxData` destructured nine keys and
   handed them to `JSON.stringify`, which silently drops every `undefined`. A
   wrong-shaped `bx.json` therefore passed both `generate` and the drift gate,
   and only `test:bx` caught it, dying at module load with 21 `tsc` errors that
   all named a *field* and never the missing tables.

## How `shared/bx.json` is regenerated (never by hand)

latte prints its own vocabulary. Build the compiler and ask it:

```bash
cd /Users/julfikar/Documents/PassionFruit.nosync/beans-lang/community-libs/latte
export BEANS_ROOT=/Users/julfikar/Documents/PassionFruit.nosync/beans-lang/beans
export BEANSC="$BEANS_ROOT/build/beansc"
export BEANS_RUNTIME="$BEANS_ROOT/runtime/beans_rt.c" BEANS_STDLIB="$BEANS_ROOT/stdlib/std" \
       BEANS_ENCODING="$BEANS_ROOT/runtime/encoding" BEANS_NET="$BEANS_ROOT/runtime/net" \
       BEANS_LOG="$BEANS_ROOT/runtime/log"
"$BEANSC" build examples/latte_bx.b -o /tmp/latte-bx
/tmp/latte-bx vocabulary > <editors>/shared/bx.json
cd <editors> && npm run generate
```

`latte-bx vocabulary` prints `bx/vocabulary.b`'s `vocabulary_json()`. latte's
own suite `tests/w2_editor_data.b` has the same string as its golden and
`tests/markup.b` §1b asks `html.b`'s predicates about every name in it, so the
JSON cannot drift from the compiler without failing latte's gate.

Verified 2026-09-08: `latte-bx vocabulary` is byte-identical to
`community-libs/latte/tests/w2_editor_data.out` (6506 bytes).
